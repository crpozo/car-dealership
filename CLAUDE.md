## How the numbers work (read before touching core.js or ingest.py)

- Every CRM report is a **month-to-date snapshot run daily**. `core.js` differences consecutive
  snapshots into per-day deltas; that is what makes day/week/custom ranges possible. A snapshot
  is keyed by (store, kind, period, begin, end, runDate); duplicate sends are dropped.
- VinSolutions workbooks are classified by their **Filters sheet** (Dealers, Date Range,
  Begin/End, Run Date, Summary Level 1), never by file name or email subject.
  `Summary Level 1 = User` → salesperson report, else KPI report.
- `period` is `current` when the report's begin month equals the run month, else `prior`.
  A scheduled report someone re-saved with a **fixed custom date range** keeps arriving daily
  but lands as `prior`, so the store silently freezes (Lunde's and Lindsay, Oct 2026).
  Staleness is therefore measured on the newest *Current Month KPI* report
  (`coverage.lastCurrent`), not on "any file arrived".
- DriveCentric sends a KPI Comparison PDF (This Month / Previous MTD / Last Month rows) and
  an Activity Report. `parse_dc_pdf` reads all pages, tolerates the Oct 2026 column change
  (New/Used Leads), and emits the **Last Month** row as the closed-month snapshot because
  deliveries post days late (the last-morning run undercounts).
- `Internet Actual Contact %` is internet-only in VinSolutions; the store total row copies it.
  Contacted is rebased on internet good leads. `Appts set of contacted %` can exceed 100%.
- Card tile **Leads** = good internet leads; **Sold** = all lead types. DriveCentric's
  "Appts Created %" is a different ratio from our "Appts set of contacted %".
- Pace = NETWORKDAYS Mon–Sat; monthly goals are prorated to the working days in the range.
  Rep sales goal default 12, store override in Settings (`repSalesGoals`).
- Matador (texts/videos/calls per rep) and Covideo (videos sent) are joined to reps by name.
  Matador CSVs older than 3 days are ignored; identical location files are deduped.
- Reynolds Focus (Herson's Honda / Kia) has no export: the crm-bots bot reads four shared reports
  off the screen per store and range (month to date + previous month) into
  `Focus <store> <report>[ <stock>] <begin> <end>.csv` with a `# key,value` header; `parse_focus_files`
  turns them into KPI (lead types Internet/Phone/Walk-In with New/Used under each; leads = Prospects
  Entered minus duplicates; no contact rate) and salesperson snapshots (calls = confirmed by telephony).
- Momentum (Vinart Group, 4 Lehigh Valley stores) emails a "Salesperson Stats MTD" CSV daily from
  a per-store sender domain. The file never names the store, so `pull.py` saves attachments from
  those domains as `<msgid>-[<domain>] <name>` and `parse_momentum` maps the domain
  (`MOMENTUM_STORES`). It emits a KPI snapshot (Totals row: Internet Prospects, Total Sales,
  Appts Created, Show Appts) plus a salesperson snapshot. Guard: byte-identical files from several
  store domains on the same day mean the schedules point at one saved report; they are skipped
  with a "Momentum:" reason that alerts once (by reason, not per file).

## Health and logs

- `pipeline/runs.jsonl` is the Logs page (admins): per run, files read, new snapshots, every
  store's newest Current Month report, rejected files vs empty exports.
- `ingest.py` writes `pipeline/.health.json`; the runner feeds it to `pipeline/health_alert.py`,
  which emails once per newly stale store or newly rejected file. Empty exports
  ("no usable rows") are benign and never alert.
- Store page → **Data sources** panel: newest file per feed, received time (from the Gmail
  message id), report range, run date, and "Open file" (API `GET /file?key=` returns a
  presigned link only for stores the caller may read).

## Users and roles

Cognito groups: `admin` (everything, Users + Logs pages), `staff` (assigned stores + Settings),
no group = `client` (assigned stores only). Store assignment is the `custom:stores` attribute
(store ids and/or group ids). Scott McDonald is always admin. Passkeys (Touch ID) are enabled
for RP `crpozo.github.io`.
